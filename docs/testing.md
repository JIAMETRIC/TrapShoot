# Testing

## The pyramid, for this app

| Level | What | How | Where |
|---|---|---|---|
| Golden | the Swift port equals the JavaScript, number for number and byte for byte | fixtures generated by `Tools/golden/generate.js`; XCTest compares | `TrapCoreTests` |
| Unit | rules, codecs, maths, mapping, validation, policies | plain XCTest, no I/O | every package |
| Integration | SwiftData in memory, HTTP through `StubURLProtocol`, files in a temp folder | XCTest with real frameworks, no network | `TrapDataTests`, `TrapWeatherTests`, `TrapPlatformTests` |
| Detector regression | the timer gives the same call and shot times on real range recordings | `Tools/detector-fixtures/*.json` + audio, fed through `FileAnalyzer` (the live detector from a file); `DetectorRegressionTests` skips until fixtures exist, its synthetic call-and-shot test always runs | `Tools/detector-fixtures/` (recordings pending, `/detector-fixtures`), `ShotTimerTests` |
| UI | the range flow on screen: direction, result, NO TARGET, Undo, the timer readout | XCUITest `TrapShooterProUITests` against `DemoTimer` in `-demo -uitest` mode, identifiers `screen.element.name` | app UI test target; CI step "UI test" |
| Performance | budgets in `docs/performance.md` | `measure {}` with `XCTClockMetric`, `XCTMemoryMetric` | `TrapCoreTests` |
| Manual, on the range | DJI receiver, route changes, latency, sunlight readability | checklist in `docs/app-store.md` | TestFlight |

## Rules

1. A port of a JavaScript function lands with its fixture and test in the same commit (write the test first: it is
   generated from the reference, so the test precedes the Swift. That is the TDD loop here).
2. `AudioDetector.swift` changes land with the regression run's numbers in the pull request.
3. Tests do not touch the network, the real microphone or the shooter's store. Stubs and in‑memory containers only.
4. A failing golden test means the Swift is wrong, not the fixture, unless the reference JavaScript changed on purpose.
5. One assertion message per check that names the round, target or case, so a failure reads like a sentence.

## Running

```sh
swift test --package-path Packages/TrapCore
swift test --package-path Packages/TrapData
swift test --package-path Packages/TrapWeather
cd Packages/TrapPlatform && xcodebuild -scheme TrapPlatform -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

CI runs the same (`.github/workflows/ci.yml`) plus a check that the fixtures are current.

## Scripted timer for UI tests

`ShotTimerControlling` lets a UI test drive the Record screen without a microphone. `DemoTimer` (demo mode) with the
launch argument `-uitest` answers every arm 0.4 s later with `firstShot` 612 ms and a `target` 612 / 1034 ms, so the
test can assert that the readout shows the time and that direction and result land in the ledger. Accessibility
identifiers follow `screen.element.name`: `record.direction.left`, `record.result.hitFirst`, `record.noTarget`,
`record.skip`, `record.retime`, `record.undo`, `record.previous`, `record.next`, `record.start`, `record.newRound`,
`record.target.N` (ledger rows, 1-based), `timer.start`, `timer.arm`, `timer.stop`, `timer.readout`. The tests live in
`TrapShooterProUITests/` and run on an iPhone simulator through the app scheme (`-only-testing:TrapShooterProUITests`).
