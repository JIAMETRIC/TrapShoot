Short answer: 39 skills and 13 agents, and they guide the 10 phases (0–9) mainly through the Mac workflow.

3. Phases (10)

The master plan has ten phases. Each one has an exit gate that is checked on a real iPhone, not only in the simulator. The full plan is in docs/phases/README.md; each phase has its own file.

Phase 0 · done

Discovery, architecture and decisions

Pillars: system design, software engineering, OOP. The architecture decisions ADR-001 to ADR-016 are written, and the plan, design system and engineering documents are in the repository. Nothing is left to do.

Exit gate: the decisions are written and filed.

Phase 1 · done (design preview not rendered)

Foundation, tooling and design tokens

Pillars: core mobile systems, software engineering, tablet and responsive design. The baseline 7.0.7 builds, CI is green, and the breakpoints are published. The design preview still needs rendering in light and dark on the Mac. That is stage 6 of mac-build, done by design-reviewer.

Exit gate: the baseline builds, CI is green, and TrapDesign renders in light and dark.

Phase 2 · done

Pure domain core

Pillars: OOP, data structures and algorithms, software engineering. TrapCore holds the round session, the schemes, the codec, break distance, CSV and analysis, and it imports no UI or storage code. Golden tests check it against the JavaScript reference. On the Mac, stages 1 to 3 of mac-build keep these tests green.

Exit gate: all golden fixtures pass, the RoundSession tests pass, and TrapCore has no UI or storage imports.

Phase 3 · done (device timing pending)

Local store and repositories

Pillars: system design, data structures, core mobile systems, software engineering. SwiftData stores the rounds, with summaries, search, paging and a transactional saveMany. Its rollback tests pass in CI. The 2,000-round timing still needs the phone.

Exit gate: summaries, search, paging and saveMany rollback tests are green, and the import of 7.x shapes works.

docs/phases/phase-3.md
Phase 4 · tests green, device pending

Shot timer engine

Pillars: OOP, core mobile systems, data structures. The reference receiver is the DJI Mic Mini 2. The remaining tasks are to record the regression set from the owner's recordings, feed each file through the detector, add a test target that checks every fixture against 7 ms (first shot) and 3 ms (call onset), and run the device checks: phone mic, DJI plugged in before and during timing, unplugged during timing, a phone call, Low Power Mode, and one hour of continuous timing. The detector itself is not to be changed without the regression run.

Exit gate: every fixture is within tolerance; the four receiver scenarios recover (restart within 0.5 s); battery stays under 10 % per hour of timing; no allocation in the audio callback.

docs/phases/phase-4.md
Phase 5 · next

Record and Timer screens

Pillars: OOP, core mobile systems, tablet and responsive design, software engineering. The first native screens replace the web view. RecordModel saves after every entry, the Timer screen shows the readout and the audio check, and kill-and-resume restores the round from the store. On iPhone it is a tab view; on iPad a split view with a sidebar. The remaining work is the range check, the device check and the iPad layout at 820 and 1180 pt.

Exit gate: a full 25-target round recorded on a real range; kill the app mid-round and reopen it, with the same round, target and times; the iPad split layout is checked; the UI test drives a round through a scripted timer.

Phase 6 · after 5

Rounds, Analysis, Schemes and exporters

Pillars: data structures, tablet design, software engineering. The rounds list must open its first screen within 50 ms with 2,000 rounds. The scorecard PDF text must be selectable, and the CSV output must match the web app byte for byte for the same round.

Exit gate: the 2,000-round first screen is under 50 ms; the scorecard PDF text is selectable; the CSV is byte-identical to the web app for the same round.

Phase 7 · after 6

Settings, data and platform behaviour

Pillars: core mobile systems, system design, software engineering. Backup and restore must round-trip the whole library. The lifecycle, notification, power and network policies must be observed on the phone. The Web folder is deleted in this phase.

Exit gate: backup and restore round-trip the library; the lifecycle, notification, power and network policies are seen on the device; the Web folder is deleted.

docs/phases/phase-7.md
Phase 8 · after 7

Release engineering and the App Store

Pillars: core mobile systems, software engineering. The app goes to a TestFlight external beta that three shooters pass. The review notes and privacy answers are filed, and the submission is accepted. Every archive and upload goes through mac-release with the owner's yes.

Exit gate: the external beta is passed by three shooters; the review notes and privacy answers are filed; the submission is accepted.

Phase 9 · ongoing

Operate and iterate

Pillars: all. Crash-free sessions must stay above 99.5 % over three months, and support bundles are answered within two days. The iCloud sync option is evaluated here and nowhere else. The work is run with the operate skill and support-triage.

Exit gate: MetricKit crash-free sessions above 99.5 % over three months; support bundles answered; iCloud sync evaluated.
